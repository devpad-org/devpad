---
title: AI settings and usage
summary: Provider keys, the models agents run on, budgets that stop them, and what your AI use costs.
---

AI settings belong to you, not to the server: your keys, your default models and your budgets apply to every agent you run (the assistant, your tasks' agents and their reviews), and to no one else's. They're under **Settings > AI**.

## Provider keys {#provider-keys}

Agents call AI providers with your own API key, so each provider bills you for what your agents use. Devpad supports **Anthropic**, **Mistral AI**, **MiniMax**, **Moonshot AI** and **OpenAI**. Add a key for each provider you want to use under **Settings > Provider Keys**.

- Keys are stored encrypted and never shown again, not even to you.
- Every request is sent with the key of the user whose run it is, looked up afresh for each request. Removing a key stops your runs on that provider at their next request.
- A key marked **Enter again** can no longer be read, which happens when the server's encryption key changes. Enter it again.

You can only pick models whose provider you have a key for.

## Default models {#default-models}

**Settings > Default Models** sets the model and reasoning effort each built-in agent runs with, unless whoever starts it picks another:

- **Coding Agent** writes and changes code. Tasks run on it.
- **Code Review Agent** reviews a change without modifying it. Reviews run on it.

An agent can start sub-agents for parts of its work. A sub-agent always runs on a model from the same provider as the agent that starts it, so an agent on an Anthropic model can start one on another Anthropic model but never on a MiniMax one. The agent sees those models with their prices, reasoning efforts and whether they read images, so it can pick a cheaper model or a lower effort for simple work. When it picks none, a sub-agent runs on your default for its agent if that is from the same provider, and otherwise on the agent's own model.

A card marked **Devpad default** follows devpad's choice among the models you have keys for. **File summaries** picks the model agents' `summarize_file` tool uses to read a file for them; **Automatic** picks the cheapest priced model you have a key for. Its cost counts toward the budget of the run that asked for it.

## Budgets {#budgets}

A budget is what an agent may spend, in US dollars, before it stops. **Settings > Budgets** sets three, each counting the sub-agents a run starts:

| Budget | Default | Covers |
|---|---|---|
| Per task | $20 | Every run of a task's agent, across retries and rounds of feedback, and every review of its merge request. New tasks start with it, and you can raise it on each task. |
| Per review | $5 | One review agent on a merge request. A review of a task's change also spends from the task's budget. |
| Per assistant reply | No limit | The assistant's work on one message. |

Leave a budget empty for no limit. A run that reaches its budget stops after its current request, and the project shows **Budget reached** with what it spent. Raising the budget lets it go on where it stopped: a task's agent when you start the task again, a review when you continue it.

Whatever the budgets, a run stops after 500 model requests. Requests to models devpad has no prices for aren't counted toward a budget, so for those that limit is the only one.

## Model pricing {#model-pricing}

**Settings > Model Pricing** lists what each model costs per million tokens (input, output, cache reads and cache writes), which devpad uses to cost each run and keep it within its budget. Prices are built into devpad and updated with it: they can't be edited, so check your provider's bill for the final word.

## Usage {#usage}

**Usage** in the header shows what your AI requests have cost, by day, week or month, for all projects or one. It shows the total, the average per period, the number of requests and tokens, a chart of cost by model, and a table by project and model.

Every request is recorded when it's made and kept after its workspace, task or project is deleted, so usage stays accurate. Each user sees only their own usage, admins included.
